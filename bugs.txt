- Deploy source commits used `fastpush`/`git add .`, so unrelated dirty app files
  could ship after icon preflight. Limit commits to the bumped version file and
  preflight-reported icon files. Regression: `tests/deploy_icons_test.sh`.

- Didact 0.4.12+45 and 0.4.13+46 stopped after GitHub created draft releases,
  before either APK upload completed. The public releases API used by Updater
  omits drafts. A retry uploaded assets to an existing draft but never published
  it, while a normal deploy also forced another version bump. Preserve assets by
  tag with checksums, resume the same draft, publish it explicitly, and verify
  the remote bytes and final non-draft state. Regression:
  `tests/deploy_release_test.sh`.

- Updater cached resolved apps without the build cohort. Replacing an `all`
  build with a tailored build could therefore show the old, wider app list until
  the next successful check. Store the cohort with the cache and reject entries
  from another cohort. Regression:
  `updater/app/src/test/kotlin/dev/jim/updater/StateCacheTest.kt`.

- Didact split APKs could pass the build step with a missing native library,
  recreating the SQLite import failure after a dependency or packaging change.
  Inspect both ABI APKs for SQLite, PDFium, Flutter, and app libraries before
  copying or publishing them. Regression: `tests/deploy_didact_native_libs_test.sh`.

- The local deploy script still pointed Sentry at its old checkout path, so
  release version bumps could target a missing project. Use the current
  `stable/sentry` checkout. Regression: the maintained-app importer test.
